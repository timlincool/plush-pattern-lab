# Stage 6：FreeCAD 原生 flatmesh 与 Blender ABF 真实同源 A/B

**状态：2026-11-13 已经在受信 main GitHub Actions 完成真实对照。仅研究证据，不是工厂纸样；P3 in_progress，P4 not_started。**

## 研究方法

真实成功 [独立运行 #43362970238](https://github.com/timlincool/plush-pattern-lab/actions/runs/43362970238) 使用现有受信 Stage6 [#43359212094](https://github.com/timlincool/plush-pattern-lab/actions/runs/43359212094) 的 N15/N17 左右耳根×内/后/外三开缝，共12个**相同**的三维Source圆盘和ABF UV。不重新划缝、删面、拼顶点；先验证三个已知输入 SHA256，来源的原Blend SHA `38a0be58ed4cb6b3af66fc392f4820d544851715002ee8520543d7e9fba85f3a`。

外部环境固定为[goatchurchprime 开源 Fork](https://github.com/goatchurchprime/blender-seams-to-sewing-pattern/tree/0ea2585105a13e03cf017cca53da684b31eb97df)的Nix文件，真正从 `cache.nixos.org` 取得**FreeCAD 1.0.0**原生二进制，调用其 pybind11 `flatmesh.FaceUnwrapper(...).findFlatNodes(10, 0.95)`，输出源顶点索引对齐的 `ze_nodes`；该实现**先 LSCM 再10轮 relax**，不能称为与LSCM无关的新算法。GPL Fork 与 LGPL FreeCAD 的求解器源码未复制/改写进本仓。

两种算法的12片结果共用原现有 `stage6_external_uv_benchmark._metrics` 计算：全局单一等比例长度归一化、三角边P95误差、同一原三维切缝两侧二维长度差、翻面与正面积重叠，研究门槛仍是 **P95≤10%、双侧缝长差≤3%、无翻转重叠**。该数值不是实际布料与工厂容差。

## 工程结论与下一步

**不将 FreeCAD flatmesh 设为默认**：它降低内部边长失真，但显著恶化本轮多数原切缝两侧长度一致性，12/12没有一个同时通过制造研究预筛。也不把 ABF 的简单净缝较好误称制造通过。它们是不同失真目标的工程权衡，下一步应优先用既有开源 Panel/Interface 结构**调整真实分片与切缝**，而非新造第4种UV或改大验收阈值。

最大真实限制仍是：原 Stage6 头颈/躯干源外形失配、鼓起蹄底、耳云尾及10个雨滴、布料方向/伸长/缝份/返口/填充、实体首样均未验证。此轮没有材料实体试验，也没有工厂纸样。

永久数据证据：Run #43362970238 Artifact `stage6-freecad-flatmesh-isolated-research`，7天留存，内含真实12组二维原顶点数组及每例共同指标；原始成员 SHA256：`flatmesh_12_real_disks.json` 为 `437876ee19819c09d97b591dd35d9170d10cafe03a0b20deb1e0cc8d60810cb2`，`freecad_vs_abf_same_source.json` 为 `b5ad5c8b181188b4ff12176a376309de26cf96a330ecf50b54a31a477f4f2991`。

只允许在可信 main 的有限时独立工作流运行，绝不把该实验加入整个 Stage6 必需依赖或生产 ETL/打版路径。
