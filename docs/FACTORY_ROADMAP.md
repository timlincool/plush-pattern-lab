# 云朵羊驼 · 从原创设计图到厂商量产的总路线图

> **唯一长期路线图（Single Source of Truth）**。真实状态请读取 [结构化进度](PRODUCTION_PROGRESS.json)；厂商文件格式与验收请读取 [工厂交付清单](FACTORY_HANDOFF.md)。本文件是未来任何 AI Agent、贡献者或厂商理解本项目时的**第一入口**，不是制造认证。

**产品目标**：约 25 cm 的原创云朵羊驼，以 `design/reference-v25/images/original-design.png` 为最初视觉目标、`selected-D-appearance.png` 为历史选定外观参考。保留 10 枚短扁布片连接的水滴、绣花五官、合成非动物材料。最终工厂在指定面料和经签核的图纸下能够重复制作**一致的标准样品**，而不是把一个 Blender 渲染解释成量产图。

**唯一开发仓库**：`timlincool/plush-pattern-lab` 的 `main`；旧私有仓库仅是历史灾备，禁止双线开发。**成功标准是实际缝制样品及厂商签核，不是单测数量或 UV 展平 P95**。

## 两个终点不能混淆

- **可向厂商询价**：有参考图、目标尺寸、目标材料和预估规格即可获取**初步**报价，今天可以启动；不等于纸样可用或正式报价锁定。
- **工厂可直接打样的 V1 技术包**：必须有完整角色分片、1:1 裁片净缝/裁切线、件数/镜像/缝份/缺口/毛向、BOM、刺绣与水滴连接、工艺顺序、测量与验收表。供应商仍需用其机器、样布、填料进行适配。
- **量产锁版**：工厂首样／必要修版后，生产文件、选定面料、验收公差和**实物标准样品 Golden Sample**版本一致。适用市场的检测及资质另行确认。

## 关键原则：先让整个角色可缝，再优化极小局部

任何局部接缝几何都只能作为真实角色分片的**一个部件**。先固定主要造型、找出所有待缝部件、形成首版真实裁片；不再将四蹄 8 组局部三角环带优化作为全项目主线。允许局部工厂手工修片，但任何手工修订必须记录版本、裁片尺寸和实物差异，不得丢失来源。

## 已有的实际可复验成果

- 设计：`design/reference-v25/` 七份说明与四张 PNG；历史 D 外观参考具有出处，但**并非已签核的四视图生产设计**。
- 源模型：本仓库 [Stage6 公开 Release](https://github.com/timlincool/plush-pattern-lab/releases/tag/cloud-alpaca-stage6-visuals-20261028) 单文件 89,853,017 字节，SHA-256 `38a0be58ed4cb6b3af66fc392f4820d544851715002ee8520543d7e9fba85f3a`，Blender 4.3.2 受信环境独立重开。
- 四蹄：主体和四蹄有 4×512 点几何接口且误差 0mm；8 个局部三角环带使用单切缝二维候选，P95 **2.28%–3.47%**，**不是**完整角色纸样，最差边约 9.31%。广泛与局部加权 A/B 的负结果已经归档。
- 合成试布：12片+2帽片可生成 1:1 A4/Letter **合成椭球**纸样，但 Blender 接触审计仍检出穿插，不能冒充真实角色纸样或量产准备。
- 代码质量：[266/266 Python 测试及 Ruff 门禁](https://github.com/timlincool/plush-pattern-lab/actions/runs/41396615974)（2026-11-02），证明的是软件回归而非工厂生产。

## 立即优先级（下一步做什么）

1. **现在开发 P2**：在受信任的 Blender Runner 对已验 Stage6 做**全场景对象与曲面盘点**，记录总数/类型、重要可编辑网格、每个重要零件的尺寸与拓扑提示；不得把“名字像云朵”当作已确认生产片。产出可审阅的轻量 JSON 而不是上传全部原始坐标。
2. **并行启动 P1**：向候选工厂索取**实际支持的裁床/纸样格式（包括 DXF 的具体版本/层约定）、刺绣格式、默认缝份、毛绒面料样卡、允许的样品修改轮数与报价范围**。未确认前只生成中立 SVG/PDF 研究文件，不猜测厂家设备。
3. **以 P2 证据确定 P3 的最小完整样件**：不是再做“外圈 2% 边权重”优化；先设计真实头身+腿蹄主壳所需裁片和拼缝，再补耳、云团和装饰。
4. **尽早交厂商做工程首样**：真实样布与实物反馈决定弹性与填充，确保后续投入在最影响外观和成本的点上。

## 时间与成本，非承诺

若一人主导数字开发、厂商配合且大体外观已确定：从现在到**可正式打样的完整 V1 技术包**暂估 6–10 周；厂商首样/修版及生产锁版可能再需要数周，整体 2–4 个月量级。**此估计未经具体厂商确认，不是项目交付承诺**。应把“首样费、打版费、修改轮数、MOQ、面料、物流、版型所有权”作为工厂报价对比项。省钱核心是减少反复解释需求和返工，而不是用 AI 假装无需样品。

## 永续进度更新协议（AI/人类均须执行）

- **进入本仓后的第一件事**：读本文件、[PRODUCTION_PROGRESS.json](PRODUCTION_PROGRESS.json)、[FACTORY_HANDOFF.md](FACTORY_HANDOFF.md)，再读与该任务相关的 Skill、源码及真实 CI。Agent 不应凭过去聊天记忆决定当前状态。
- 每当一个 PR 合并且**真实证据齐全**：在**同一或紧接的 PR** 更新 JSON 的阶段状态、`next_actions` 和对应证据 URL/相对路径；更新此文档中已有证明。只有代码或数学函数但**没有**可审计的 3D/实物结果，写 `in_progress` 而非 `accepted`。
- 若实验失败，按原值归档失败证据，**不能删除旧反例或放宽现有门限以声称完成**。主分支构建通过≠实体制造通过。
- P1 需要用户或供应商反馈的条件，标明 `requires_factory_confirmation`；P6/P7 需要实物签核，不能凭视觉渲染或算法输出自行标绿。
- 当出现多个“最新进度”时，**该 JSON 与对应 main 提交的证据是权威版本**；旧聊天、PR 描述、历史文档均为上下文。
