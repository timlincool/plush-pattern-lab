## 第一性问题：根带增加宽度是否真的解决了制造问题？

此前 [Z230→235 真源窄带](STAGE6_TRUE_EAR_ROOT_BAND_CUT.md) 虽有四条完全配对的3D净线（源边ID、3D XYZ零误差和反向绕向），但左右两道缝的源三角边最短图路径仅5.333/5.557mm，明显小于两侧各6mm研究缝份合计12mm。它已被否决为工业根片的简易方案。

本轮不再把一个固定高度横截面当耳根，预先固定两个非水平候选。对每个原源顶点 \((x,y,z)\)，定义 \(q=\mathrm{clip}((y+45)/15,-1,1)\)，下/上切面用原源顶点高度分别计算，再按每条原三角边作**分片线性等值面插值**：

| 研究方案 | 下缘高度场（mm） | 上缘高度场（mm） |
| --- | --- | --- |
| N15 | 228.5 + 1.5q | 243.5 + 1.5q |
| N17 | 227.5 + 1.5q | 244.5 + 1.5q |

切面并非简单平面；每个交点保留原三角面 source Face ID、原 Vertex ID 边对、等值面0/1与原模型**真实世界三维毫米坐标**，两侧共享相同交点的身份。以标准化标量 \(t=(z-z_{\mathrm{low}})/(z_{\mathrm{up}}-z_{\mathrm{low}})\) 在同一原网格上严格切分 \(t<0\)、 \(0\le t\le1\)、\(t>1\)，然后把派生网格从标量空间恢复到原始世界XYZ。求交的标量场按源三角顶点线性插值，**不是对连续曲面布料的形变模拟**。

## 与旧水平切面配缝函数的关键区别

首次受信 main Run #43189646252 **失败并保留原日志**：旧水平根带的配边助手用世界坐标 \`Z==cut_height\` 筛选缝线。非水平界面的每个源交点有不同的真实 Z，因此即使原Source ID严格一致，旧助手也错误返回“源缝线不足3段”。Python CI #43189645982此前的2个合成测试也独立捕获这一问题。

本轮修复**没有**将实际源点强行投影到水平Z（那会造假）。新增专门的非水平缝线门禁：使用规范的原源边等值面身份（原Vertex ID边对 + t=0/1）选择缝边，再对物理世界XYZ、相邻源三角面绕向、完整闭合环及三角面图距离逐项重算。新反例要求旧的水平配边函数在斜面上必须失败、而新函数只能凭真实源ID配对。此处如有任何一个来源不匹配，应让Workflow失败，不能自动修边。

### 新发现：缝间宽度与耳尖宽度不能混为一谈

当我们把根带加高，底部“5mm宽两缝太近”问题改善，却把上缘切到了更细的耳状曲面：上缘XY最窄约6–7mm，**小于双侧各6mm的12mm合计**。这不是已展平布片的有效宽度，也不构成绝对不可缝的几何定理；它说明根片必须与实际**外耳/内耳独立Mesh、云层装配、布料厚度和折边工艺**共同设计，不能仅看源网格图距离大于12mm就宣称工厂纸样可用。
