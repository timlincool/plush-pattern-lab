# Stage6 R6：真实 Blender40帧单调侧头壳，接触改善但整体外形不通过

**2026-11-18｜受信原生 Blender4.3.2 Run [#44272520802](https://github.com/timlincool/plush-pattern-lab/actions/runs/44272520802) 成功；P3 在研、P4 未开始、厂商纸样0。**

## 根因与唯一改动

原 R5 两侧高位侧头壳的5层三维预定位高度为 `230→240→230→235→245mm`：先上升再返回原高度，存在明显的曲面折返。R6 使用 `230→231→232→235→245mm`，高度单调递增；保留 R3 原986条、R5总1170条缝合弹簧、40件试布及原始头身/四蹄。新层间的二维Rest Shape仍由已证明的 R5 求解器生成并独立校验；R5默认数学不变。R6把原源z230侧轮廓**平移到z232研究站位**，不是原三维精确切缝。

本地 A/B 预定位：R5 新布面有241组与理论缝合顶点无关的有限三角面相交/接触；R6 单调方案在相同静态屏检下为0。R6逐段二维新增配缝最大差约0.0000022mm，整件预定位边长变形P95约8.82%，没有降低原10.5%研究筛选线。静态通过**不足以证明物理求解后无穿插**，所以仍执行同次原生Cloth。

所有实际网格均来自 evaluated Blender Cloth。Stage6真实25%主壳只是外形比较目标，不会伪装为布壳。评价采用相同15k表面抽样和双向最近邻，mm单位：

**接触证据方法：** 本地把真实 NPZ 的全部面片扇形三角化（每版3978三角面），用 VTK 9.6.2 静态 Cell Locator 筛查包围盒，再调用 `vtkTriangle.TrianglesIntersect` 复核；排除共享Vertex ID的邻接三角面，用1170条 Sewing Springs 的 Union-Find 划分**理论缝接身份**，单独报告缝线邻近接触，而非假定已实际焊接。结果把相切/共面也计入，既不能直接称所有交点是严重体积穿透，也不能由未检出就证明有厚度/动态过程安全。原 R5真正第40帧NPZ SHA256 `137ac391acfdced61a012783502caaf3f36ca744393b3cec0b92cc0b7debc15a`，R6 `a90569d9e23a11c2e612e262a0faa48e01e55c5616cfca85d4b5541b51d5e912`；原 Stage6固定PLY `5b52e3fd09c83b19c5b9d95d6d8d859a147ff4deef90f1518f868d2e82e3a2dd`。

## 工程决策：两个基线，不同用途

- **外形基线仍保留 R5；R6 不晋升“整体最像羊驼”的版本。**
- **接触优化研究基线采用 R6 的单调侧头部过渡**。本轮减少了大量假折返自碰，但R6新片对原主体尚有15组有限面片交/触、另有6组旧主体交/触，不能通过 P3 物理完整性门禁。
- 下一轮优先定位这些15组新旧主壳见证、调整头顶孔/根部与肩头附近的路由；在真实第40帧复测穿插与外形，之后独立试开自碰、压力、实测面料。不能把增加很多静止弹性、关闭碰撞当成实物合格。
- **原始 Stage6 四块耳片、7云覆层、尾巴与水滴仍未真正进入R6物理缝合**；眼前只是源引导的两侧头部代理。主躯干仍有盒型和直腿问题。P3、P4、工厂状态保持原值。
