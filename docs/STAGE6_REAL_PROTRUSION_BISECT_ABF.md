# Stage6：真实高位突出源网格的两种省道/分片路线（P3）

**状态：待受信主干 Blender 4.3.2 实际评分；本页不含虚构的 2D 结果。原主壳和4×512蹄口完全不变。P3进行中，P4未开始；工厂正式裁布纸样0。**

## 为什么不继续更换UV算法

真实 Stage6 25%源代理，在 Z=230mm 截面得到中央189边、左113边、右112边三条源环。先前 [真实3D三片与原生ABF](STAGE6_REAL_CROWN_3D_CAPS_ABF.md) 已证明：中央1663源三角片的边长P95为4.05%，左右1849/1906源三角片 P95 为93.50%/93.91%，两侧单片不适合按当前纸样展开。这里**不改变这些既有反例**，只试改变右/左突出部分的切缝拓扑。

## 只利用已有第三方与通用库

- 输入是已受信 Stage6 的 `source_three_caps.json` 与其同轮 `source_three_caps_topology_qa.json`，校验真实源 SHA、原三角面数与 Z230 113/112环，不重新优化/平滑原雕塑。
- `validation/stage6_real_protrusion_bisect.py` 用 SciPy `dijkstra` 在**原三维三角网格内部边**寻找实际最短路径；路径由两个相对底缘源顶点经过原上部最高顶点组成。再用 SciPy `connected_components` 按真实源面共享边分成两片。仅原面重索引，**不伪造新的局部几何面**。每侧两片Euler=1、单闭环、所有原FaceID恰好一份、新切缝两侧原Source Vertex ID相同、Z230原边113/112条守恒。
- 不根据失败结果挑选端点，只预声明**Y前后极值**与**X内外极值**两种方案；均为研究切缝，未审设计参考/耳云遮挡，不能因曲面路径最短就称其为隐藏工艺线。
- `unwrap_stage6_protrusion_bisect_blender.py` **复用既有** `unwrap_stage6_true_crown_caps_blender._unwrap` 的 Blender 4.3.2 ANGLE_BASED，绝不新写UV。
- `audit_stage6_protrusion_bisect_abf.py` **复用既有** `_scale_free_gauge` 和 `_face_overlap_and_winding`；每片用单独的全局等比例Gauge计算真实原边P95、翻转、正面积重叠；新源切口两侧按原Source Vertex路径对齐后计算**每段2D净缝长度差**，而不只是3D缝一致或总周长。

## 否决条件与后续工作

必须报告两路×左右侧×各两片＝**8组ABF真实源三角形**，不能只挑某一片通过。门槛仍保持边长P95≤10%、无翻转与重叠，新切缝双侧每段累计绝对差≤原3D源缝的3%。这里的3%属于预筛值不是工厂材料公差。**下部连续主壳7开口的对应二维净线仍不存在**，原Z230外缘尚无真正两侧二维接口，研究结果即使改善，也不能称为整只玩偶可裁、可填棉。
